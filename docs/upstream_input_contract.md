# Upstream Input Contract — chem-literature

## 1. Authority

The only corpus discovery/selection authority for Feature_create is the final file generated by:

[chem-literature](https://github.com/Tuzhidingdong/chem-literature)

The current upstream final artifact is:

\`research_corpus_paired.csv\`

The current chem-literature \`run_workflow.py\` writes this CSV in its working directory. It also writes the corresponding files under \`papers_pdf/\` and \`papers_si/\`. The current code does not emit a separate \`research_corpus_paired_manifest.json\`; Feature_create must not require one.

The downstream \`source_manifest.json\` is an internal derived artifact created from this CSV and the files it explicitly references. It is not an independent paper-discovery input.

## 2. Required columns

The current upstream code populates these columns:

| Column | Required downstream | Meaning |
|---|---:|---|
| \`doi\` | Yes | DOI used as the preferred stable paper key |
| \`title\` | Yes | Article title |
| \`year\` | Yes | Publication year |
| \`journal\` | Yes | Journal/source name |
| \`article_type\` | Yes | Upstream article-type classification |
| \`local_pdf_path\` | Yes | Relative or absolute path to the main full-text PDF |
| \`local_si_info\` | Yes | Relative or absolute path to the Supporting Information file |

Additional upstream columns currently include:

- \`cited_by_count\`
- \`landing_page_url\`
- \`abstract\`
- \`pdf_status\`
- \`si_status\`
- \`has_pdf\`
- \`has_si\`

Additional columns must be retained in the original CSV row metadata but do not change the Feature_create extraction schema unless an explicit contract migration is introduced.

## 3. Path resolution

The current chem-literature code returns relative paths such as:

- \`papers_pdf/10_1002_example.pdf\`
- \`papers_si/10_1002_example_SI.zip\`

These paths are relative to the working directory from which \`run_workflow.py\` is executed. Therefore:

1. The default Feature_create path base is the directory containing \`research_corpus_paired.csv\`.
2. The user may pass \`--corpus-root\` to select the exact directory against which relative paths are resolved.
3. Absolute paths are accepted as supplied.
4. Feature_create does not search neighboring directories for alternate files.
5. Missing paths are preserved as blocked source records and prevent Worker A/B dispatch for that paper.

## 4. Pair integrity

The paired CSV is upstream-curated and must remain the complete paper selection boundary.

Feature_create performs only physical integrity re-checks:
- the listed main PDF exists and begins with PDF magic bytes;
- every listed SI path exists;
- listed ZIP archives are valid and can be safely expanded within configured limits.

Feature_create must not:
- recursively inventory all PDFs or SI files in the upstream working directory;
- add files not referenced in the paired CSV;
- independently search for SI by DOI or filename;
- replace a missing SI file with a similarly named file;
- repeat upstream article-type screening or remove papers based on its own topic/quality judgement.

If a CSV-listed path is missing, invalid, or not extractable, record the precise failure. Do not silently drop the corresponding paper.

## 5. SI file handling

Current upstream publishers may return PDF, DOCX, ZIP, XLSX, or other binary SI resources. The current harvester stores one discovered SI path per CSV row. Feature_create accepts one path and also tolerates JSON arrays or semicolon-separated path lists for forward compatibility.

For ZIP SI:
- retain the original archive path and file hash in the manifest;
- extract only supported members into the downstream run directory;
- reject path traversal, symlinks, excessive member count, and excessive uncompressed size;
- preserve the relationship between each extracted member and its originating archive;
- do not alter the upstream SI archive.

For DOCX/XLSX and text/table sources, retain the original file and create a text/table representation for semantic review.

## 6. Identity and provenance

- Preferred \`paper_id\`: normalized DOI.
- Each source gets a stable ID derived from paper identity, source role, path, and file hash (or a visible missing/invalid status).
- The internal manifest records the upstream CSV path and SHA-256, original CSV row metadata, file paths, hashes, parse status, and derived text locations.
- Worker tasks retain the original DOI, title, year, journal, article type, source IDs, and original file provenance.

## 7. Expected command

Example when chem-literature was run from \`E:\\Zinc_batters_datas\\chem-literature\`:

\`\`\`powershell
python scripts/prepare_corpus.py \`
  --paired-csv "E:\\Zinc_batters_datas\\chem-literature\\research_corpus_paired.csv" \`
  --corpus-root "E:\\Zinc_batters_datas\\chem-literature" \`
  --output "E:\\Zinc_batters_datas\\runs\\Feature_create\\prepared"
\`\`\`

A malformed CSV, missing required columns, or unreadable input file stops preparation. A CSV row whose PDF/SI file is missing is preserved in the manifest as blocked pair integrity and is not dispatched to a semantic worker.
