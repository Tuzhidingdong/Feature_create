# Upstream Input Contract — chem-literature Preprocessed Package

## 1. Authority and required upstream version

The only paper-selection authority is the final `research_corpus_paired.csv` generated by [chem-literature](https://github.com/Tuzhidingdong/chem-literature/tree/feat/chem-literacy-preprocessing-stage).

Feature_create requires the chem-literature preprocessing stage to have completed and written a package for each paired paper. A CSV produced by the harvesting-only `main` branch is insufficient. Do not fall back to parsing the PDF/SI files when preprocessing columns or package files are absent.

The handoff is the combination of:
1. `research_corpus_paired.csv` — authoritative list and paper metadata;
2. each row's `preprocessing_path` — path to `01_preprocessing/`;
3. `evidence_index.json` — structured source/page/table/figure/SI index;
4. `PREPROCESSING_QC_REPORT.md` — source-processing coverage and warnings;
5. the parsed text, table exports, and media assets referenced by the package.

The current source package version is `1.1.0`.

## 2. Required CSV columns

| Column | Required | Meaning |
|---|---:|---|
| `doi` | Yes | Preferred stable paper key |
| `title` | Yes | Article title |
| `year` | Yes | Publication year |
| `journal` | Yes | Journal/source name |
| `article_type` | Yes | Upstream article classification |
| `local_pdf_path` | Yes | Original MAIN PDF provenance path |
| `local_si_info` | Yes | Original SI provenance path(s) |
| `preprocessing_path` | Yes | Relative or absolute path to the paper's `01_preprocessing/` package |
| `preprocessing_status` | Yes | Status written by the upstream preprocessor |
| `preprocessing_qc_report` | Recommended | CSV path to the package QC report |

Other CSV fields, including `abstract`, `landing_page_url`, `has_pdf`, and `has_si`, are retained as paper metadata. Feature_create does not re-run literature discovery or article screening.

## 2A. Optional deterministic paper-level sampling

The complete paired CSV remains the authoritative upstream inventory. When it contains thousands of preprocessed papers, `scripts/sample_corpus.py` can produce an explicit subset before preparation.

- Default sample fraction: 10% of eligible unique papers, rounded to the nearest whole paper (minimum one by default).
- Sampling unit: normalized DOI; when DOI is absent, normalized title + year + journal.
- All CSV rows sharing one paper identity are selected together.
- Default proportional stratification: `year`. Use `--stratify-by none` for global sampling or provide comma-separated metadata columns.
- Stratum quotas use D'Hondt divisor allocation, which is house-monotone: for a fixed source corpus, increasing the fraction cannot reduce a stratum's quota. Combined with fixed per-paper hash ranks, each larger sample is a superset of the smaller sample.
- Rows with missing `preprocessing_path` or unsupported/failed preprocessing status are excluded before calculating the sample size and appear in the manifest with reasons.
- The default seed is `feature-create-v1`. Identical input bytes, seed, fraction, and strata reproduce the same selected paper set.

The sampler reads CSV metadata only. It does not open or hash source PDFs, SI, or preprocessing packages. It writes a cumulative sample CSV, a newly-selected incremental CSV, and `sampling_manifest.json`, which records the source/sample hashes, per-paper decision/score, stratum quotas, parent-manifest fingerprint, previous/current selected keys, and exclusion reasons.

For a later round, use the incremental CSV as the preparation input; use the cumulative CSV only when intentionally rebuilding the entire sample. Preparation detects which view was supplied, verifies its SHA-256 and paper-key set, and records cumulative plus applied-view provenance in `source_manifest.json`. For sample expansion, the source CSV bytes, seed, strata, and `min_papers` must remain unchanged and the fraction must increase. Preserve the previous manifest and cumulative CSV; changed or missing parent artifacts block expansion. Prepare an incremental CSV in a new run directory, then reconcile it into the same persistent Registry/Records. Existing full-corpus runs remain valid without a sampling manifest.


## 3. Path resolution

The current chem-literature workflow writes CSV file paths and `preprocessing_path` relative to the working directory from which `run_workflow.py` was executed.

- By default, Feature_create resolves relative values against the CSV directory.
- `--corpus-root` explicitly overrides that base.
- Absolute paths are accepted as supplied.
- Feature_create never scans adjacent folders for substitute files.

Example:

~~~powershell
python scripts/prepare_corpus.py `
  --paired-csv "E:\Zinc_batters_datas\chem-literature\research_corpus_paired.csv" `
  --corpus-root "E:\Zinc_batters_datas\chem-literature" `
  --output "E:\Zinc_batters_datas\runs\Feature_create\prepared"
~~~

## 4. What Feature_create validates

Feature_create performs package and provenance validation only:

- CSV row DOI agrees with the package metadata DOI when both are supplied.
- The package directory, `evidence_index.json`, and QC report exist.
- Package version and processing status are supported.
- CSV `preprocessing_status` equals `evidence_index.processing_summary.status`.
- The CSV-listed raw MAIN PDF and SI files physically exist.
- Their SHA-256 hashes match `inventory.main_pdf` and `inventory.source_supplementary_files` in the upstream evidence index.
- Every referenced image asset exists and matches its upstream SHA-256.
- Table export paths are checked when present; structured table rows embedded in the evidence index remain authoritative.
- All package-relative paths are constrained to the package directory.

Raw PDFs and SI archives are opened only for a short magic-byte check (MAIN PDF) and hashing. They are not parsed, rendered, unpacked, or attached to worker tasks.

A mismatch in the raw pair blocks the paper as `blocked_pair_integrity`. A missing/invalid preprocessing package blocks it as `blocked_preprocessing`. An otherwise valid package with scanned pages or unsupported SI can proceed as `ready_with_warnings`; those limits must remain visible to both workers and the final audit.

## 5. Upstream evidence that must be preserved

The internal Feature_create manifest preserves source IDs and pointers to:

- `main_analysis.md` and `si_analysis.md`;
- each structured table's `table_id`, `doc_type`, `page_number`, `bbox`, caption, and exact `rows`;
- each figure's `figure_id`, `doc_type`, `page_number`, `bbox`, and caption;
- all `media_assets` asset IDs, types, relative paths, hashes, extraction methods, dimensions, figure/table IDs, and captions;
- `pages` with page indices, page numbers, dimensions, scan flags, text blocks, and block bounding boxes;
- `si_references` linking MAIN text locations to SI labels;
- processing summaries, warnings, scanned-page counts, and unsupported supplementary materials.

The complete upstream `evidence_index.json` is copied byte-for-byte into `upstream_evidence_indexes/` and attached to each corresponding worker task. Its page and coordinate information must not be flattened away or regenerated by Feature_create.

## 6. Worker input boundary

Worker A and Worker B receive:
- exact upstream-extracted MAIN and SI text;
- exact structured table rows and table content;
- figure captions and pre-extracted image assets;
- the upstream `evidence_index.json`;
- the upstream QC report and warnings;
- stable Feature_create source IDs that map to the upstream records.

Workers do **not** receive raw MAIN PDFs, raw SI PDFs, SI ZIP archives, or original DOCX/XLSX files as document-parsing inputs. They must not launch a second PDF/SI parser or claim that a raw source was reviewed merely because the raw file exists.

Scanned pages and unsupported SI are explicit coverage gaps. The existence of a page image or an extracted asset does not prove that it was visually interpreted.

## 7. Internal Feature_create source manifest

`source_manifest.json` is a downstream index derived exclusively from the curated CSV and its referenced preprocessed packages. It is not a second corpus-discovery source.

Logical source records include:
- MAIN and SI parsed-text components;
- individual upstream structured tables;
- figure captions;
- image/media assets.

Raw PDF/SI inputs are recorded separately in each paper's `raw_source_inventory` with their hashes and `worker_attachment: false`. They are not included in semantic worker coverage as parsed content.

`extracted_text/` stores exact text staging copies used by the evidence validator. It is not a new parser output. `upstream_evidence_indexes/` stores exact copies of upstream evidence-index JSON files.

## 8. Stop and warning conditions

Block the paper when:
- preprocessing columns are absent;
- the package or evidence index/QC report is missing;
- package schema version or preprocessing status is unsupported;
- DOI or raw-source hash integrity conflicts;
- required MAIN parsed text is missing;
- an upstream asset hash is wrong.

Preserve as warnings/unresolved coverage:
- `WARNING_SCANNED_PAGES` (upstream performs no OCR);
- `PARTIAL_SI_UNSUPPORTED`;
- `PARTIAL_NO_SI`;
- absent table exports when structured table rows still exist in the evidence index;
- individual missing optional media assets.

Never silently mark a partial package complete, infer that unsupported SI was read, or fall back to reparsing the original PDF/SI.
